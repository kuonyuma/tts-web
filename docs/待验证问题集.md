## 1. 真实核验结论汇总

### 1.1 部分成立判断的真实机制与边界（P01–P13）

| 编号 | 待验证问题/推论 | 真实核验结论 | 处理决策 |
|---|---|---|---|
| P01 | TTS 双轨都是冗余 | 否。Legacy 提供匿名共享缓存、TTL 与重播；Private 提供 owner 隔离与 LRU，两者有不同业务契约。 | 维持双轨架构，不盲删 Legacy。 |
| P02 | Private 内存缓存完全无价值 | 否。内存层复用不可变 bytes 减少 Python 堆分配；同时磁盘 SHA-256 校验能即时捕获外部保留 mtime 的损坏。 | 保留设计契约。 |
| P03 | RLock 令所有请求全面串行 | 否。存储阶段同一 store 串行，但上游网络合成在锁外并发执行。 | 保持存储事务锁，不扩大范围。 |
| P04 | 文件备份和恢复属于过度设计 | 否。SQLite 回滚无法撤销文件覆盖，临时文件和 backup 真实保护原子发布与损坏恢复。 | 保留备份恢复机制。 |
| P05 | 五重控制都是重复锁 | 否。同键锁、进程内并发、分布式配额、存储容量与上游信号量保护不同层级的资源。 | 保持分层保护。 |
| P06 | 硬编码 1000 导致永久 503 | 否。1000 是可配置默认值；新存档报 507，已有缓存正常返回 200；且 PR #13 已补齐 DELETE 释放端点。 | 保持容量保护与释放端点。 |
| P07 | gateway 是虚假抽象 | 否。gateway 承担实际提供商调用并包装四元组。但内部存在模型参数与 selection 的微小重复表达。 | 保留网关接口，收敛调用传参。 |
| P08 | 404 墓碑无限制增长 | 否。受认证、CSRF、限流和 DB_MAX_BYTES 保护，且 PR #13 已增加定期修剪机制（`prune_tombstones`）。 | 保持墓碑回收策略。 |
| P09 | 请求体预缓冲是中间件侵入 | 否。在 JSON 解析前限制实际字节数与慢速上传，属于准入防护。 | 保留请求体控制。 |
| P10 | 多种时间格式代表混乱 | 否。UTC 日期桶用于统计，epoch 用于到期判断，各司其职；PR #13 已统一绝对事件时间 helper。 | 保持统一 helper。 |
| P11 | TTS/LLM 异常与运行时完全复制 | 否。运行时核心已通过 `runtime.py` 共用；不同业务的公开 HTTP 状态码与提示文案不同。 | 保持业务异常映射独立。 |
| P12 | 配置多且 GLM 是死代码 | 否。GLM 有完整真实调用链路，显式启用即可到达。 | 保持模型注册表可扩展性。 |
| P13 | 密码锁串行登录是缺陷 | 否。Argon2 内存消耗大（约 64 MiB/次），全局锁有意保护容器不发生 OOM。 | 保持单 worker 内存锁。 |

### 1.2 确认存在并已解决的问题清单（F01–F22 中剩余项）

| 编号 | 问题主题 | 真实验证情况 | 解决方案与实施状态 |
|---|---|---|---|
| **F09** | 追问账本与消息分开提交，恢复协议不完整 | **真实存在**。`api/explain.py` 先调用 `record_usage` 后调用 `append_chat_messages`，分属两个独立事务。若消息更新失败或会话被删除，用量已被计入产生幽灵调用。 | **已修复**。将 `_upsert_daily_usage` 逻辑收敛至 `append_chat_messages` 内部，在单次 `begin immediate` 事务中原子执行。若会话不存在则不计费并回退。 |
| **F06** | 开发 JWT 密钥只读查询申请 SQLite 写锁 | **真实存在**。`auth_service.signing_key()` 在未配置显式 secret 时，每次读取均申请 `write=True` 写锁（`begin immediate`），阻塞并发只读认证。 | **已修复**。采用 Double-Checked 模式：先通过 `write=False` 读连接查询，仅在缺失时申请写连接生成并插入。 |
| **F16** | 私有历史时间索引不匹配实际排序 | **真实存在**。`private_tts_migrations.py` 建立了 `idx_tts_history_owner(owner_id, last_played_at desc)`，但实际查询按 `assets.last_access_ns desc` 排序，该索引从未被查询使用，但在每次 touch 时被更新。 | **已修复**。在迁移中移除该索引创建，并执行 `drop index if exists idx_tts_history_owner` 清理旧库。 |
| **F17** | 私有淘汰循环每选一项就重做用量聚合 | **真实存在**。`_prune()` 在淘汰循环中对每个 victim 均调用 `_usage()` 执行全表 `SUM(byte_size)` 与 `COUNT(*)`。 | **已修复**。`_oldest` 补充查询 `byte_size`，循环中直接递减容量计数，避免全表反复聚合。 |
| **F02** | 普通身份 helper 的 Header 声明和异步包装无实际作用 | **真实存在**。`require_client_id` 被声明为 `async` 并带 `Header(...)`，但从未通过 `Depends()` 注入，内部无异步 I/O。 | **已修复**。重构为同步验证函数 `validate_client_id`，保留同步/异步兼容别名，消除无用开销。 |
| **F03** | 邮件可用性判断重复实现 | **真实存在**。`api/auth.py` 的 `/config` 路由独立判断 `bool(settings.SMTP_HOST and settings.SMTP_FROM)`。 | **已修复**。统一调用 `mail_service.mail_enabled()`。 |
| **F04** | 引擎集合双源维护、固定 PCM 位宽假参数 | **真实存在**。`schemas/tts.py` 硬编码引擎元组；`gemini_engine.pcm_to_mp3` 声明无用 `sample_width` 参数且仅支持 2。 | **已修复**。引擎验证统一委托 `get_engine()`；移除 `pcm_to_mp3` 的假参数 `sample_width`。 |
| **F05** | 共享认证依赖跨层分散、服务层反向导入私有符号 | **真实存在**。`articles.py` 与 `users.py` 从 `auth.py` 路由跨层导入依赖；`auth_service.py` 导入 `limits.py` 私有符号 `_resolve_client_ip`。 | **已修复**。认证依赖统一集中到 `api/dependencies.py`；`limits.py` 暴露公共 `resolve_client_ip`。 |

## 2. 核心修改文件

- `src/app/services/explain_service.py`: `append_chat_messages` 原子化记账与消息追加 (F09)
- `src/app/api/explain.py`: 移除多余的独立 `record_usage` 调用，接入原子化接口 (F09)
- `src/app/services/auth_service.py`: `signing_key` 读操作避免申请写锁 (F06)；使用公用 `resolve_client_ip` (F05)
- `src/app/services/private_tts_migrations.py`: 废除无用的 `idx_tts_history_owner` 索引 (F16)
- `src/app/services/private_tts_storage.py`: 优化淘汰循环，避免逐项全表 SUM/COUNT (F17)
- `src/app/api/dependencies.py`: 规范化同步 client_id 验证 (F02)；集中收敛 `current_account` / `admin_account` / `auth_request_guard` (F05)
- `src/app/api/auth.py`: 复用 `mail_enabled` (F03)；重导出依赖 (F05)
- `src/app/api/limits.py`: 暴露公用 `resolve_client_ip` 函数 (F05)
- `src/app/api/articles.py` / `src/app/api/users.py`: 从 `dependencies.py` 导入认证依赖 (F05)
- `src/app/schemas/tts.py`: 引擎校验委托注册表 (F04)
- `src/app/services/engines/gemini_engine.py`: 清理 `pcm_to_mp3` 无用 `sample_width` 参数 (F04)
- `tests/test_explain.py`: 新增针对 F09 原子追问与记账的边界测试用例
- `tests/test_auth_security.py`: 新增针对 F06 只读密钥无写锁争抢的测试用例

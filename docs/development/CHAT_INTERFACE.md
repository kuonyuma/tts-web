# 会话式 TTS 界面

## 设计

沿用原生 ES modules、现有引擎 / BYOK 设置、API 请求超时和客户端 ID。
会话及用户消息保存在 `tts_conversations_v1:<client_id>` localStorage 中；每个用户消息内含稳定 ID、原文、提交时间、生成参数和对应音频状态。音频仍使用后端缓存，通过带 X-Client-ID 的请求加载为临时 Blob URL，不把音频或 API Key 写入会话。

文本无自动过期时间。音频缺失只改变卡片状态，重试沿用原参数。刷新时未完成任务变为可重试状态。删除会话只删除本地记录，不清理可能被其他消息复用的音频。清除浏览器数据会删除会话；本轮不提供跨设备同步。

首次成功读取旧历史后，将接口返回的最近 50 条按生成时间升序放入“历史记录”会话。记录迁移标记，避免删除会话后重新导入。请求失败不标记成功，提供重试。原后端历史不删除。

左右栏桌面占据各自宽度，收起后中间伸展；窄屏同时最多打开一个抽屉。中间消息独立滚动，底部输入固定。卡片原位更新，仅在接近底部时跟随滚动。

侧栏与遮罩使用 260ms 过渡。设置中的“界面动效”提供跟随系统（默认）、开启、关闭；显式开启可覆盖浏览器仍报告减少动态效果的情况，偏好保存为 `tts_motion`。关闭时即时禁用交互并恢复焦点，动画完成后隐藏。前端静态资源使用 `Cache-Control: no-cache` 与 ETag，在刷新时重新校验未带版本的模块，避免新版 HTML 混用旧版脚本。

AI 绑定当前会话最新消息的 ID，只传该条原文。更换目标使旧请求及动画失效；输入草稿、播放旧语音、收起展开侧栏均不改变 AI 目标。自动开关控制自动请求，关闭时仍可手动解说和提问。

`POST /api/explain` 和 `GET /api/explain` 新增可选 `context_id`（1–128 个 ASCII 字母、数字、下划线或连字符）。前端使用会话 ID 与消息 ID 的组合，后端将其纳入解释记录键，隔离相同文本的追问历史。不传该参数时沿用旧键；无需数据库迁移。客户端身份验证不变，范围标识不代替身份验证。

## 重点审查

- 同文本、不同会话的 AI 晚返回也必须失效。
- 删除进行中的会话不能被请求完成后复活。
- 存储失败必须显示错误，不得悄悄丢弃用户文本。
- 音频网络失败允许重新加载；404/410 提供重新生成。
- 旧卡片保留引擎和音色，修改设置只影响新消息。

以下前端检查全部通过。浏览器使用独立临时配置、模拟 API 和合成 WAV，无真实 TTS / AI 请求。

`uv run pytest -q --tb=short`：280 passed，2 条第三方弃用警告。按后续要求补齐 `stop.bat` 后，原先因文件缺失失败的四项检查已通过，另新增同一 PID 去重和终止失败报告的测试。进程查询及终止命令使用模拟，不会停止实际运行的服务。

在项目目录执行 `.\stop.bat`，检查 8000 端口并复用 `scripts/verify_tts_process.ps1` 校验进程归属。仅停止使用本项目虚拟环境、运行 `app.main:app` 且 `--app-dir` 为本项目 `src` 绝对路径的 Uvicorn 进程；无法确认归属时跳过。相对路径启动、其他端口及 Docker 容器不在该脚本的停止范围内。

独立代码审查后修复并添加回归验证：可选 AI 目录不再阻塞 TTS 初始化；手机抽屉关闭后恢复键盘焦点；相同文本不同消息的 AI 追问记录隔离。原静态资源测试和旧前端交互测试已更新为会话界面契约。
